Integrations

FEED — long videos, host-only

Powers real photo/video uploads in the Feed. Up to 4 Cloudinary accounts, tried in order — if #1 fails (quota hit, misconfigured, etc.), it automatically tries #2, then #3, then #4. Leave any of them blank if you only need one or two; empty slots are just skipped.

How to get these (free, no credit card, ~2 minutes each)
  1. Go to cloudinary.com and sign up for the free plan — a separate free signup (different email) for each backup account you want.
  2. Your Cloud name is shown right on the Dashboard home page after signup.
  3. Go to Settings → Upload, scroll to Upload presets, click Add upload preset.
  4. Set Signing Mode to Unsigned, leave the rest default, and Save. Copy its name.
  5. Paste the cloud name and preset name into any slot above and hit Save.

TODAY'S QUESTION — a daily prompt to pull everyone in

Every day, once it's past 7pm, a new question appears in a pinned "Today's Question" chat automatically — the AI writes it using the family facts from the AI tab, and everyone gets a notification. If it's not been answered much by 8pm, there's a gentle reminder too.

CALENDAR — location for zmanim & holiday times

Zmanim (sunrise, candle-lighting, etc.) depend on an exact location. Defaults to New York City — change it if your family is elsewhere.

CHAT — everyone's photos, videos & voice messages

Kept separate from the Feed's Cloudinary setup on purpose — this way everyday chat attachments never eat into the Cloudinary quota reserved for long Feed videos. Until this is set up, Chat quietly uses Cloudinary as a fallback; once you add this, Chat switches to it automatically.

How to get these (free, no credit card, ~3 minutes — one step is easy to miss)
  1. In your Supabase project, go to Settings → API. Copy the Project URL and the anon (or newer publishable) key — never the service_role/secret key, that one must never leave your server.
  2. Go to Storage → New bucket. Name it (e.g. family-board) and mark it Public.
  3. Easy to miss: marking a bucket "Public" only allows reading files — uploads still need their own permission. Open the bucket → Policies → New policy → choose the template for INSERT access → allow it for the anon role → Save. Without this step, uploads will fail with a "row-level security" error.
  4. Paste the URL, key, and bucket name above and hit Save.
